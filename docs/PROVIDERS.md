# Provider support matrix

Updated 2026-11-05. Fresh settings select OpenRouter speech and OpenAI notes; existing saved selections remain unchanged. Deepgram is no longer selectable; existing runs and backups remain readable. Synthetic tests do not establish live access or quality.

| Role | Default | Optional | Output and limits |
| --- | --- | --- | --- |
| Transcription | OpenRouter `/api/v1/audio/transcriptions`, `elevenlabs/scribe-v2` | OpenAI `/v1/audio/transcriptions`, `gpt-transcribe`; configurable model ID | One original file up to 25 MB. OpenAI provides text with no assumed speakers or timestamps. Scribe requests diarization and word timestamps. Missing metadata stays unknown. Model/format support varies. |
| Memo | OpenAI Responses `gpt-6-luna` | OpenRouter Responses `openai/gpt-6-luna`; configurable model ID | Selected model must support strict JSON schema. Generated content, citations, and refusal/incomplete results are validated before saving. |
| Local review | Text/structured transcript | Existing backed-up runs, including Deepgram | No key or network required. |

Both stages have independent provider/model selections and provider-specific keys saved unencrypted in this browser's separate IndexedDB database. The fresh preset requires OpenRouter and OpenAI keys. A custom model ID is user supplied; the app does not guarantee compatibility or account access. OpenAI's `gpt-4o-transcribe-diarize` is selectable for temporary use but is deprecated and scheduled to stop on 2027-02-26. Do not interpret plain text as diarization or infer timestamps.

Provider words or segments with equal start/end times retain their text and speaker labels, with both timing fields normalized to unknown. They remain available for review and citation, without an invented playback range. Positive-duration ranges remain unchanged; negative, nonfinite or reversed times still reject the response. A saved real Scribe response and synthetic browser regressions exercise this boundary; see [validation](VALIDATION.md).

OpenRouter passes content to upstream providers. Its transcription routing options do not have the same control contract as text routing; actual upstream and retention depend on the selected service and account. For Responses, the app requests `allow_fallbacks: false`. The app itself never automatically resubmits a paid request. Timeouts, cancellation and broken connections remain possibly chargeable. The 25 MB cap applies before either upload; imported audio up to 50 MiB may remain stored locally and be played back. No arbitrary byte slicing or automatic remote upload is performed.

Provider costs and model availability vary; a speech estimate requires a known duration and a user-entered USD-per-minute rate bound to the selected model, with a source URL and checked date. Otherwise it is unknown. Memo cost remains unknown before submission. Keys never enter backups, logs, worker caches or build artifacts. Users explicitly confirm the recipient, model, data, and possible charge before each cloud operation.

### Planned preset and usage evidence — 2026-11-05

The requested starting combination is OpenRouter `elevenlabs/scribe-v2` for speech and OpenAI `gpt-6-luna` for notes; it is the fresh-settings default and an optional preset. Saved selections and custom values are retained. The implemented preset and cost controls offer English and Simplified Chinese; broader application localization and assistive-technology certification remain open. Local/offline checks exercise bounded compaction on one long recording; the paid long-recording memo request predates the current fragment-array transport and does not validate it. The 80,000-character input limit still applies and does not establish support for arbitrary-length recordings. See [validation](VALIDATION.md) for scope and semantic-review limitations. Do not infer diarization accuracy or model access for other accounts.

OpenRouter documents a `usage` object for transcription and Responses that can include duration, token counts, cache counts and `cost` in USD; parse validated fields when present and label a returned cost as provider-reported for that request. [OpenRouter usage accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting). OpenAI Responses documents token usage, but a response without a dollar charge remains unknown; show the usage, and only compute a separately labeled estimate when complete applicable rates and usage are available. [OpenAI response reference](https://developers.openai.com/api/reference/resources/responses/methods/create), [OpenAI pricing](https://developers.openai.com/api/docs/pricing). Prices and account conditions change: retain rate source, effective/checked date, currency and assumptions, distinguish estimates from reported request costs and final billing, and never invent zero for missing fields. Do not require organization-admin billing credentials or introduce a backend to display per-request usage.

An independent user [reported](https://github.com/murtaza-nasir/speakr/issues/168) a 1,400-second duration error for `gpt-4o-transcribe-diarize`. This is a historical third-party report, not a verified current OpenAI limit. For longer recordings, the confirmation displays an advisory without blocking the user or splitting audio. The provider's `chunking_strategy=auto` is not local file splitting. If a provider rejects a request, the app classifies only known error categories and displays fixed guidance; raw provider response bodies are not stored or displayed. Unknown errors remain unknown, and submitted requests may still incur charges.

Live release gates: valid-key production-origin CORS, account/model access, consented Chinese/English recordings, diarization accuracy, actual costs, interrupted real requests and physical devices. No development keys are created; the user tests the finished website. Synthetic tests only establish app orchestration.
