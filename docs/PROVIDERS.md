# Provider support matrix

Updated 2026-11-05 for the user's OpenAI-default/OpenRouter-optional decision. Deepgram is no longer a selectable endpoint; existing Deepgram runs and backups remain readable. These are documented request contracts and synthetic tests, not evidence of live access or quality.

| Role | Default | Optional | Output and limits |
| --- | --- | --- | --- |
| Transcription | OpenAI `/v1/audio/transcriptions`, `gpt-transcribe` | OpenRouter `/api/v1/audio/transcriptions`, `elevenlabs/scribe-v2`; configurable model ID | One original file up to 25 MB. OpenAI default provides text with no assumed speakers or timestamps. Scribe requests diarization and word timestamps. Missing metadata stays unknown. Model/format support varies. |
| Memo | OpenAI Responses `gpt-6-luna` | OpenRouter Responses `openai/gpt-6-luna`; configurable model ID | Selected model must support strict JSON schema. Generated content, citations, and refusal/incomplete results are validated before saving. |
| Local review | Text/structured transcript | Existing backed-up runs, including Deepgram | No key or network required. |

Both stages have independent provider/model selections and provider-specific keys saved unencrypted in this browser's separate IndexedDB database. The default requires only an OpenAI key. A custom model ID is user supplied; the app does not guarantee compatibility or account access. OpenAI's `gpt-4o-transcribe-diarize` is selectable for temporary use but is deprecated and scheduled to stop on 2027-02-26. Do not interpret plain text as diarization or infer timestamps.

OpenRouter passes content to upstream providers. Its transcription routing options do not have the same control contract as text routing; actual upstream and retention depend on the selected service and account. For Responses, the app requests `allow_fallbacks: false`. The app itself never automatically resubmits a paid request. Timeouts, cancellation and broken connections remain possibly chargeable. The 25 MB cap applies before either upload; imported audio up to 50 MiB may remain stored locally and be played back. No arbitrary byte slicing or automatic remote upload is performed.

Provider costs and model availability vary; speech rate is an optional user-entered locally saved estimate, not a cap. Memo cost remains unknown before actual usage. Keys never enter backups, logs, worker caches or build artifacts. Users explicitly confirm the recipient, model, data, and possible charge before each cloud operation.

### Planned preset and usage evidence — 2026-11-05

The requested starting combination is OpenRouter `elevenlabs/scribe-v2` for speech and OpenAI `gpt-6-luna` for notes; this is a proposed preset, not the current default. Preserve saved user selections and custom values. Local validation notes report a successful browser Scribe run and a separate OpenAI memo request, but the full long-recording-to-memo workflow remains blocked by the memo input limit. Those detailed notes may not be present in every checkout. Do not infer diarization accuracy or model access for other accounts.

OpenRouter documents a transcription `usage` object that can include duration, tokens and `cost` in USD; parse validated fields when present and label a returned cost as provider-reported for that request. [OpenRouter transcription guide](https://openrouter.ai/blog/tutorials/transcription-on-openrouter/). OpenAI Responses documents token usage, but the observed OpenAI memo response did not provide a dollar charge; show the usage, and only compute a separately labeled estimate when complete applicable rates and usage are available. [OpenAI response reference](https://developers.openai.com/api/reference/resources/responses/methods/create), [OpenAI pricing](https://developers.openai.com/api/docs/pricing). Prices and account conditions change: retain rate source, effective/checked date, currency and assumptions, distinguish estimates from reported request costs and final billing, and never invent zero for missing fields. Do not require organization-admin billing credentials or introduce a backend to display per-request usage.

An independent user [reported](https://github.com/murtaza-nasir/speakr/issues/168) a 1,400-second duration error for `gpt-4o-transcribe-diarize`. This is a historical third-party report, not a verified current OpenAI limit. For longer recordings, the confirmation displays an advisory without blocking the user or splitting audio. The provider's `chunking_strategy=auto` is not local file splitting. If a provider rejects a request, the app classifies only known error categories and displays fixed guidance; raw provider response bodies are not stored or displayed. Unknown errors remain unknown, and submitted requests may still incur charges.

Live release gates: valid-key production-origin CORS, account/model access, consented Chinese/English recordings, diarization accuracy, actual costs, interrupted real requests and physical devices. No development keys are created; the user tests the finished website. Synthetic tests only establish app orchestration.
