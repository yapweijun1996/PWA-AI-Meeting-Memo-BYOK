# SSOT design system and PWA gap assessment

Assessment date: 2026-11-16. Baseline: local `main` at `125d71c`, including the uncommitted voice-analysis locking changes. This is a documentation assessment, not an implementation or publication of the recommendations.

## Conclusion and scope

**Partially aligned; full compliance is not established.** The application has semantic colors, light/dark appearance, shared primitives, speaker/workflow presentation helpers, responsive layouts and browser tests. It lacks the complete token/component ownership and automated enforcement described by the relevant KB standards. Selected passing tests do not establish whole-application design quality.

This assessment covers the SSOT standards discussed in this conversation and the project's PWA release contract. A separate [voice identity logic register](#voice-identity-logic-gap-register--2026-11-16) was added on 2026-11-16 from a code reading at `db9e5a5`. It does not claim to audit every standard in every KB. Other projects' architecture, exact palettes, component names and admin-panel navigation are reference material, not automatically binding requirements for this meeting workspace.

## Voice identity logic gap register — 2026-11-16

Scope: meeting-scoped anonymous voice matching only, read at `main` `db9e5a5`. This section details REL03's "labelled matching evaluation" and quality items; licensing and deployed download stay under REL03. Cross-meeting recognition is out of scope and governed by [its evaluation plan](docs/SPEAKER-PROFILE-EVALUATION.md). IDs are shared with [task.md](task.md#voice-id-production-hardening--2026-11-16).

**Conclusion: working prototype, not production quality.** The pipeline runs end to end, but nothing measures whether its groupings are right, several decisions rest on evidence the code itself weakens, and human corrections do not feed back into matching.

Evidence labels: **Code** = read in the named function on 2026-11-16, not reproduced by a test. **Observed** = the one real recording in [the handoff](docs/HANDOFF.md#5-evidence-and-its-limits). **Fixture** = seen with fake vectors in a unit test. None of these is an accuracy measurement, and no fix below is proven to help until VID01 exists.

Pipeline as implemented: provider labels per part → `selectAcousticSamples` (up to 6 windows of 1.5–4 s per label per part; 3 before 2026-11-16) → `decodeAcousticWindow` (16 kHz mono) → WavLM vector (512 values, unit length) → `matchLabelsAcrossParts` for multi-part recordings with two or more labels in some part, otherwise raw-cosine `clusterRecordingSources` / `chooseAcousticAssignment` → `applyAcousticAssignments` as one undoable revision → review hints from `suggestVoiceMatches`.

## Applicability decisions

- Preserve this project's approved 52px/56px topbar and meeting workflow badges unless a new product decision changes them. Different admin-panel dimensions are not defects here.
- K2's native-control prohibition is a library ownership rule from another implementation. This React application intentionally wraps a native `<dialog>` in shared `Modal`. Keep its tested accessibility; assess repeated disclosures/fields as ownership gaps rather than replacing native semantics solely for stylistic compliance.
- The JSON token pipeline is an exact K1 implementation gap. Authoritative CSS plus enforcement can satisfy the SSOT principle if explicitly adopted as a documented local adaptation; it must not be reported as implementing K1's generator.
- No compliance percentage is reported: optional features, project-specific rules and missing verification have different meanings.

## Verification evidence and limits

- This audit read the exact versioned K1/K2 records and inspected tracked paths, package scripts, selected source and existing test assertions. It did not modify application code or fix the gaps.
- PASS on 2026-11-16: `npx playwright test tests/browser/theme-token-roles.spec.ts`, 2/2 cases across Chromium and Windows WebKit. Each case exercises two themes and four palettes for selected status/button/focus contrasts and palette-independent speaker/status colors. This uses the existing local static build from the preceding voice-lock task; no app source changed during this audit. It is not a complete contrast or visual review.
- PASS: `git diff --check` for the documentation additions. Existing unrelated uncommitted implementation changes were preserved.
- Earlier in this conversation, the voice-lock change passed 279 unit tests, lint, build, artifact checks, focused Chromium/WebKit concurrency/recovery tests and both-engine PWA lifecycle checks on Node 25. These results are reused only for their covered behavior; they are not a new full design-system acceptance run.
- Full UI screenshots, exhaustive contrast, physical devices, actual model quality, deployed model download and pinned-runtime release checks were not run by this documentation audit.
