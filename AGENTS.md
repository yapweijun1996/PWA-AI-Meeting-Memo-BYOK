# Project instructions

- Always reply to the user in Mandarin Chinese. Write code, code comments, and identifiers in English.
- End every user-facing reply with exactly four next-step options labeled A, B, C, and D.
- Use `src/components/Masonry.tsx` and its stylesheet as the single source of truth for collections of independent cards. Preserve source and keyboard order, respond to content and viewport changes, and use one column on narrow screens. Structured form panels and fixed summary tiles are not independent card collections.
- Keep palette keys, labels and defaults in `src/appearance-preferences.json`, color values in `src/theme.css`, and language choices in `src/ui-language-options.ts`. The runtime favicon and sidebar brand share brand-mark roles; do not add a second color map. Installed/Apple icons remain separate static assets.
- Reuse `ChoiceMenu` for single-choice action menus and preserve native form controls where appropriate. Extract presentation modules without moving feature-owned provider drafts, speaker confirmation, playback or revision state into shared UI components.

- This project is a browser-first, speaker-aware meeting memo PWA with runtime BYOK and GitHub Pages hosting. Keep the normal user workflow usable without installing a companion or running a backend.
- Owner direction, 2026-11-10: long recordings must support automatic, meeting-scoped speaker identity continuity across processing chunks; manual listening, enrollment, or merging must not be the required normal workflow. A single-upload size increase does not satisfy this goal. Design for bounded per-chunk resources and resumable processing, and disclose tested storage, duration, provider, and device limits rather than promising literally unlimited input.
- Prefer a fully browser-operated PWA, using verified browser inference or direct third-party APIs where suitable. The owner approved a lightweight backend as a fallback for third-party identification, long-running jobs, and cross-chunk coordination when validated browser or provider limitations require it; it is not a mandatory default or authorization to spend, provision infrastructure, or deploy. Verify the actual processing and recovery path before choosing that fallback; backend-dependent features must be explicit.
- Automatic speaker matching must use acoustic evidence, preserve original provider output and human edits, and support undo and revision invalidation. Matching names, provider labels, or overlapping transcript words alone does not establish voice identity. Preserve ambiguity and overlapping speech; do not claim a person's real-world identity or retain cross-meeting voiceprints by default.
- Read [README.md](README.md), [docs/PRODUCT.md](docs/PRODUCT.md), and the documents relevant to a change before implementation. The 2026-11-04 browser-first decision takes precedence over older companion-first proposals.
- Treat the proposed stack, provider capabilities, and future module names as plans. Verify current official documentation and real browser behavior before claiming support.
- Keep speaker correction, source evidence, revision invalidation, local recovery, and export in scope. Preserve original model output separately from human edits.
- The user explicitly chose unencrypted provider-key persistence in this browser's IndexedDB. Make the shared-origin risk clear; keep keys out of meeting backups, source control, Actions secrets for frontend injection, public build artifacts, logs, and service-worker caches.
- A GitHub Pages repository path is not an origin security boundary. Scope this app's worker/cache/database names and never delete unrelated origin storage.
- Paid requests with unknown outcomes must not automatically retry, including retries inside SDKs. Provider polling and resubmission are different operations.
- Use the GitHub Pages base path consistently for assets, worker registration, manifest identity, and navigation. Production routing must work on a static host.
- Preserve drafts before user-triggered PWA updates. Verify offline use and the version N to N+1 update flow; manifest presence alone is not PWA completion.
- Apply the acceptance matrix in [docs/ROADMAP.md](docs/ROADMAP.md), including iOS standalone, safe areas, accessibility, and storage recovery. Record unsupported behavior explicitly.
- The workflow under `docs/examples/` is inactive. Activate it only alongside a runnable app, its required checks, and authorized publication. Documentation work alone does not establish deployment success.
- Report checks actually run and remaining limitations. Do not commit, push, or deploy without authorization from the current task or existing session instructions.
- For the speaker voice-matching work, read [docs/HANDOFF.md](docs/HANDOFF.md) first. Do not claim matching accuracy: none is measured. Do not publish the WavLM weights until their licence is established. In a shared working tree, run long local analyses from a static build (the dev server reloads on every save), stage explicit files, and reconcile with `origin/main` in a clean worktree.

## Quality-first product contract — 2026-11-17

- Follow [goal.md](goal.md) and [docs/QUALITY-FIRST-PLAN.md](docs/QUALITY-FIRST-PLAN.md). The target is a Pi-Orchestrated, Multi-Model, Evidence-Grounded Meeting Intelligence Platform.
- Prioritize LLM-first understanding, Pi-first orchestration, browser-first operation, measured multi-model routing, meaningful multi-pass analysis and final human review. Do not skip necessary analysis/context or select weaker models to reduce cost.
- Owner follow-up, 2026-11-17: Pi review may use up to 100 cumulative provider attempts per persisted plan. This is an execution ceiling, never a quality target or instruction to consume all attempts. Preserve initial BYOK/data consent, no-progress/duplicate guards, physical resource boundaries and the ban on automatic resubmission of unknown outcomes. Continuation, reload and backup must not reset the count.
- Verify browser Pi core/adapters in source and runtime; do not assume a CLI, shell, filesystem or arbitrary-code agent is browser compatible or authorized. LLM tool calls remain meeting-scoped and validated.
- Preserve complete originals, speaker provenance and protected human facts. Require full-source coverage accounting, claim-level evidence, independent review and recoverable checkpoints; model self-scores never substitute for human reference evaluation.
- Treat model roles as logical stages, not a mandate to spawn eight agents. Route OpenAI/OpenRouter by actual capability and benchmark evidence; no silent provider/model fallback outside consent.
- Keep planned capabilities distinct from shipped behavior. Use [docs/QUALITY-EVALUATION.md](docs/QUALITY-EVALUATION.md) for quality gates and record real provider/device gaps without claiming production readiness.
