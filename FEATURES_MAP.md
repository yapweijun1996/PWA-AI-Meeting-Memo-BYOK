## Reading the map

- **Implemented**: the inspected source contains the described path. It does not mean every configuration or acceptance criterion passed.
- **Partial**: a path exists but a stated part of the capability, validation, or operational boundary remains open. The progress cell says which.
- **Planned / absent**: a desired or optional capability has no corresponding end-to-end implementation in this snapshot. A prototype or evaluation document alone is not implementation.
- The **progress** text describes implemented scope and remaining work rather than a percentage. Test file references identify available coverage; they are not claims that those tests ran for this map.
- **Complete application acceptance for this mapping: NOT_RUN.** Synthetic Node.js and local Chromium/WebKit probes reproduced a long-recording restore defect; their evidence and limits are in `docs/VALIDATION.md`. No provider request, physical-device test, model download, or deployment verification was performed for this mapping. Prior results apply only to their recorded source/build and test scope in `docs/VALIDATION.md`.
- Feature IDs below are stable identifiers for this document, not application APIs. Routes and labels are source-backed; a renamed route or feature should trigger a map review. The intended actor is a person using their own browser profile; the app has no application-level user-role or tenant system. Provider access requires the relevant account/key, connection, supported model, and explicit consent; local review does not require a provider key.
- Dependencies are functional prerequisites, not a promise that browsers, providers, model licenses, or accounts are currently supported. In particular, an unavailable recording, unknown timestamp, unavailable Web Locks, denied storage, or uncertain paid request must remain an explicit state rather than fabricated evidence or an automatic retry.

## Product and dependency overview

`#/` is the meeting library; `#/meetings/<id>` opens a meeting; `#/settings` opens settings. New meeting, restore, help, and PWA status are actions in the application shell. Meeting tabs are **Transcript**, **Speakers**, and **Meeting notes**. Settings tabs are **Appearance**, **API & models**, **Storage**, and **About**. See `src/App.tsx`, `src/features/MeetingWorkspace.tsx`, and `src/features/Settings.tsx`.

The main data flow is: local import → optional confirmed cloud transcription → local transcript/speaker review → optional confirmed memo generation → evidence review → export/backup. The browser owns the IndexedDB records and foreground job state; GitHub Pages serves static assets; only explicitly selected third-party services process submitted data. Optional local voice matching uses an in-browser worker and meeting-scoped acoustic data. The PWA service worker caches the application shell, not provider responses.
